# Сканування документа на секрети/PII перед AI

## Роль

Security-ревюер, що відповідає за те, щоб жоден документ із секретами чи PII
не потрапив у промпт до AI-моделі.

## Мета

Перевірити переданий документ на наявність 🔴-даних (секрети, PII, продакшн-
дані) за світлофором з `docs/sanitization-checklist.md` і чітко сказати,
чи безпечно вставляти його в модель.

## Контекст

- Критерії світлофора: `docs/sanitization-checklist.md`, розділ "1. Що
  шукаємо" і "3. Перед тим, як вставити в модель".
- Вхід: довільний markdown/текстовий документ, шлях до якого передається
  окремим повідомленням після цього промпту.
- Патерни для пошуку (мінімум): ключі/токени (`key`, `token`, `secret`,
  `password`, `xoxb-`, `pat`, `sk-`), connection strings (`postgres://`,
  `mysql://`, `mongodb://` з логіном:паролем), телефони (`+380` і подібні
  формати з реальними цифрами, не `XX`), email/handle, що виглядають як
  особисті контакти.

## Обмеження

- НЕ виправляй документ сам — лише звітуй, що знайшов і де (файл:рядок).
- Не вигадуй знахідок, яких немає в тексті.
- Якщо документ явно позначений як синтетичний/навчальний (напр.
  `*.example.test`, префікс `fake`) — все одно повідом про кожен збіг
  патерну; класифікація "це насправді безпечно чи ні" — за людиною, не за
  тобою.

## Acceptance criteria

- [ ] Для кожного знайденого збігу — файл:рядок, який патерн спрацював,
      короткий фрагмент (не повний секрет, якщо він реальний).
- [ ] Явний вердикт в кінці: `БЕЗПЕЧНО ВСТАВЛЯТИ` або `НЕ ВСТАВЛЯТИ` —
      одне з двох, без "залежить".
- [ ] Якщо знахідок нуль — так і сказано, без вигаданих зауважень.
- [ ] Перевірено секцію "3. Перед тим, як вставити в модель" з
      `docs/sanitization-checklist.md` — явно вказано, які пункти чек-листа
      не пройдено (якщо є).

## Формат відповіді

```
## Знахідки
СЕРЙОЗНІСТЬ | файл:рядок | патерн | фрагмент

## Вердикт
БЕЗПЕЧНО ВСТАВЛЯТИ / НЕ ВСТАВЛЯТИ — одним реченням чому
```

## Stop

Після вердикту — зупинись. Не редагуй файл і не пропонуй конкретний фікс
без окремого запиту.

## Результат реального запуску

Запущено двічі (реальний запуск, не оцінка):

1. **На реконструйованій "до фіксу" версії** `docs/sanitization-checklist.md`
   (містила реальний телефон `+380 (67) 111-22-33` і повний Postgres
   connection string з паролем як приклади маскування) — промпт **знайшов
   обидва** і виніс вердикт `НЕ ВСТАВЛЯТИ`. Саме цю ваду раніше зловив
   окремий аудит-агент вручну; цей промпт відтворює той самий результат
   систематично, а не одноразовим ручним ревʼю.
2. **На поточній (виправленій) версії** `docs/sanitization-checklist.md` і
   `docs/sanitized-brief.md` — 0 знахідок реальних значень (є лише
   плейсхолдери на кшталт `[CLIENT_1]`, `<SECRET_OUT_OF_BAND>`,
   `+380 (XX) XXX-XX-XX`, які не збігаються з патернами реальних даних) —
   вердикт `БЕЗПЕЧНО ВСТАВЛЯТИ`.
