# Сканування документа на секрети/PII/внутрішню логіку перед AI

## Роль

Security-ревюер, що відповідає за те, щоб документ ішов лише в модель того
tier, який відповідає найвищій категорії даних у ньому.

## Мета

Класифікувати переданий документ за світлофором з
`docs/sanitization-checklist.md` (🔴/🟡/🟢) і чітко сказати, для якого tier
моделі його безпечно вставляти — а не лише "безпечно чи ні".

## Контекст

- Критерії світлофора: `docs/sanitization-checklist.md`, розділ "1. Що
  шукаємо" і "3. Перед тим, як вставити в модель".
- Вхід: довільний markdown/текстовий документ, шлях до якого передається
  окремим повідомленням після цього промпту.
- 🔴-патерни (мінімум): ключі/токени (`key`, `token`, `secret`, `password`,
  `xoxb-`, `pat`, `sk-`) зі СПРАВЖНІМ значенням (не плейсхолдер типу
  `<SECRET_OUT_OF_BAND>`), connection strings (`postgres://`, `mysql://`,
  `mongodb://` з реальним логіном:паролем), телефони/email/handle з
  реальними (не `XX`-маскованими) цифрами/адресами, рядки вигрузки з
  реальними іменами/сумами.
- 🟡-патерни (мінімум): назви конкретних внутрішніх систем/постачальників
  автоматизації (напр. n8n, Airtable, конкретна БД), маржа/собівартість/
  ставка з реальними числами, схеми БД, внутрішні назви гілок/сервісів.
  Назви систем, які клієнт **сам** використовує і які вже названі в описі
  задачі (напр. "CRM", "Slack" як категорія — без деталей реалізації) —
  це НЕ 🟡, а частина 🟢 постановки задачі; не плутай ці два випадки.

## Обмеження

- НЕ виправляй документ сам — лише звітуй, що знайшов і де (файл:рядок).
- Не вигадуй знахідок, яких немає в тексті.
- Якщо документ явно позначений як синтетичний/навчальний (напр.
  `*.example.test`, префікс `fake`) — все одно повідом про кожен збіг
  патерну; класифікація "це насправді безпечно чи ні" — за людиною, не за
  тобою.

## Acceptance criteria

- [ ] Для кожного знайденого збігу (🔴 і 🟡 окремо) — файл:рядок, який
      патерн спрацював, короткий фрагмент (не повний секрет, якщо він
      реальний).
- [ ] Явний вердикт в кінці — один із трьох, без "залежить":
      `НЕ ВСТАВЛЯТИ` (є 🔴), `ЛИШЕ ENTERPRISE/NO-TRAIN АБО ЛОКАЛЬНА МОДЕЛЬ`
      (є 🟡, немає 🔴), `БЕЗПЕЧНО ДЛЯ БУДЬ-ЯКОЇ МОДЕЛІ` (немає ні 🔴, ні 🟡).
- [ ] Якщо знахідок нуль — так і сказано, без вигаданих зауважень.
- [ ] Документ, що містить лише 🟡 (без жодного 🔴), НІКОЛИ не отримує
      вердикт `БЕЗПЕЧНО ДЛЯ БУДЬ-ЯКОЇ МОДЕЛІ` — це б суперечило власному
      правилу чек-листа, що 🟡 потребує enterprise/no-train або локальну
      модель.

## Формат відповіді

```
## Знахідки
СЕРЙОЗНІСТЬ (🔴/🟡) | файл:рядок | патерн | фрагмент

## Вердикт
НЕ ВСТАВЛЯТИ / ЛИШЕ ENTERPRISE/NO-TRAIN АБО ЛОКАЛЬНА МОДЕЛЬ / БЕЗПЕЧНО ДЛЯ БУДЬ-ЯКОЇ МОДЕЛІ — одним реченням чому
```

## Stop

Після вердикту — зупинись. Не редагуй файл і не пропонуй конкретний фікс
без окремого запиту.

## Результат реального запуску

Запущено на трьох версіях (реальний запуск, не оцінка; v2 промпту — з
класифікацією 🟡, після рев'ю CodeRabbit на PR, яке показало, що v1
пропускав документи з лише 🟡-даними як "безпечно вставляти", хоча
власний чек-ліст команди вимагає для 🟡 enterprise/no-train tier):

1. **Реконструйована "до фіксу" версія** `docs/sanitization-checklist.md`
   (містила реальний телефон і повний Postgres connection string з
   паролем як приклади маскування) — знайдено 🔴 (реальний телефон,
   реальний connection string) — вердикт `НЕ ВСТАВЛЯТИ`.
2. **Реконструйована "до CodeRabbit-фіксу" версія**
   `docs/sanitized-brief.md` (з розділом "Доступи (з нашого n8n,
   продакшн)", що називав n8n/Airtable/Postgres) — 0 знахідок 🔴
   (секрети вже `<SECRET_OUT_OF_BAND>`), 3 знахідки 🟡 (`n8n`, `Airtable
   Base / PAT`, `Postgres (репліка)` — конкретні внутрішні системи, не
   потрібні для постановки задачі; CRM/Slack correctly НЕ позначені 🟡,
   бо вони вже названі узагальнено в розділі "Задача") — вердикт
   `ЛИШЕ ENTERPRISE/NO-TRAIN АБО ЛОКАЛЬНА МОДЕЛЬ`, хоча заголовок
   документа тоді стверджував, що він призначений для "публічних
   моделей" — саме цю суперечність і мав ловити скан (і зловив).
3. **Поточна (виправлена) версія** `docs/sanitized-brief.md` — 0
   знахідок і 🔴, і 🟡 (секція "Доступи" переписана на узагальнені
   призначення без назв конкретних постачальників) — вердикт
   `БЕЗПЕЧНО ДЛЯ БУДЬ-ЯКОЇ МОДЕЛІ`.
