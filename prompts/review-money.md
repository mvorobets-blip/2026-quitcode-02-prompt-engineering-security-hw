# Рев'ю грошового дифу з відтворенням

## Роль

Рев'юер фінансового коду. Відповідаєш за те, щоб жоден цент не зник і не з'явився. Твоя
робота — довести дефект запуском, а не висловити підозру.

## Мета

Знайти в дифі `app/src/quote.ts` порушення грошових інваріантів і для кожного дати
команду, яка його відтворює.

## Контекст

- **Ціль рев'ю — закомічений `HEAD`, в окремій чистій копії:** `git worktree add <тимчасова тека> HEAD` і
  `cd <тимчасова тека>`. Диф, читання файлів і всі перевірки — лише звідти, тож незакомічені зміни
  користувача не змішуються з кодом рев'ю (на початку звіту — SHA `HEAD`). Наприкінці —
  `git worktree remove <тимчасова тека>`.
- Диф: `git diff 8f36e5e HEAD -- app/src/quote.ts` (стартовий код шаблону → HEAD гілки). Читай також
  повний `app/src/quote.ts` і `app/src/quote.test.ts`.
- Інваріанти домену (джерело істини, а не поточна поведінка коду):
  1. усі грошові значення — цілі числа в центах: результат `estimateTotalCents` і кожен
     платіж у масиві `splitInstallments`; рядок `formatMoney` — не число, для нього діє інваріант 4;
  2. `splitInstallments(t, n)`: довжина `n`, сума елементів дорівнює `t`, різниця між
     будь-якими двома елементами не більша за 1;
  3. `estimateTotalCents`: `Math.round` від точного значення `hours × rate × (1 − d/100)`,
     `.5` — догори; `d = 0` → без знижки, `d = 100` → 0;
  4. `formatMoney`: `-1234 → "-$12.34"`, завжди дві цифри після крапки.
- Запуск: `cd app && npm test`; разова перевірка, напр.:
  `cd app && node --input-type=module -e "import { splitInstallments } from './src/quote.ts'; console.log(splitInstallments(100, 3))"`
  (Node ≥ 23.6 імпортує `.ts` напряму, без залежностей).

## Обмеження

- Тільки читання й запуск перевірок. НЕ редагуй і не створюй жодного файла в репозиторії;
  тимчасові скрипти — лише поза ним.
- Дефект без команди відтворення — це не знахідка, а питання. Пиши його окремо.
- Не коментуй стиль, назви й форматування. Максимум 7 знахідок.
- Некоректний вхід (`parts = 0`, від'ємні `hours`, нецілі центи) — це знахідка лише тоді,
  коли функція мовчки повертає хибні гроші. Якщо контракт не визначений — це питання.

## Acceptance criteria

- [ ] Кожна знахідка має: `файл:рядок`, порушений інваріант (номер), вхід, команду
      відтворення й дослівний вивід цієї команди.
- [ ] Перевірено щонайменше: 0, від'ємна сума, залишок від ділення, межа `.5`,
      нецілий вхід, великі значення (≥ 10^9 центів).
- [ ] Для кожної знахідки сказано, чи ловить її наявний тест (`так` / `ні`, назва тесту).
- [ ] `cd app && npm test` запущено, і його підсумок наведено дослівно.
- [ ] Робоча копія користувача не змінилась — перевірено вмістом, а не лише статусом. Першою командою (в
      основній теці, до `worktree add`) зафіксовано знімок: `git status --porcelain`, `git diff HEAD | shasum` і
      `git ls-files -o --exclude-standard -z | xargs -0 shasum`; після рев'ю ті самі три виводи збігаються
      (повторна зміна вже зміненого файлу змінила б хеш, хоча статус лишився б тим самим).
- [ ] Якщо дефектів немає — так і написано, без вигаданих зауважень.

## Формат відповіді

1. Таблиця: `СЕРЙОЗНІСТЬ | файл:рядок | інваріант | вхід | факт → очікування | тест ловить?`
2. Під таблицею для кожної знахідки — команда відтворення й її вивід.
3. «Питання до власника» — неоднозначні контракти без доказу дефекту.
4. SHA `HEAD`, підсумок `npm test` і знімок робочої копії до й після рев'ю.

## Stop

Після звіту зупинись. Виправлень не пропонуй кодом — лише одним реченням на знахідку.

## Результат запуску (2026-11-23)

Прогін — на версії 1. Версія 2 (після незалежного рев'ю тексту) лише уточнює команду
дифу (`8f36e5e HEAD`), дає повний приклад разової перевірки замість `…` і дозволяє тимчасові
скрипти поза репозиторієм; суть промпту не змінилась. Версія 3 (за рев'ю CodeRabbit) уточнює
інваріант 1: цілими мають бути грошові значення в центах, а не «результат будь-якої функції».

Запущено в чистому клоні гілки (`claude -p`, Claude Code 2.1.325, Opus 5.5, `--permission-mode
default`; явно дозволено `npm test`, `node`, `git diff`, `git status`, решту read-only команд CLI пропускає сам;
тимчасові скрипти перебору агент писав у свій scratchpad поза репозиторієм). Повний транскрипт —
[`docs/runs/review-money-run.md`](../docs/runs/review-money-run.md).

Агент знайшов 4 дефекти, кожен із командою відтворення. Кожну команду після прогону повторено вручну — результати збіглися:

| Серйозність | Де | Інваріант | Вхід | Факт → очікування |
|---|---|---|---|---|
| HIGH | `app/src/quote.ts:42` | 3 | `{ hours: 1024.1, rateCents: 20485 }` | `20978688` → `20978689` (точно `…688.5`; float дає `20978688.499999996`, епсилон `1e-9` замалий) |
| MEDIUM | `app/src/quote.ts:78-79` | 1, 2 | `splitInstallments(100.5, 3)` | `[34, 34, 33]`, сума 101 — з'являються гроші |
| MEDIUM | `app/src/quote.ts:77-82` | 2 | `splitInstallments(100, 0)` | `[]` — 100 центів мовчки зникають |
| LOW | `app/src/quote.ts:97` | 4 | `formatMoney(1234.5)` | `"$12.34.5"` |

Жодну зі знахідок наявні тести не ловлять (`npm test` — 16 passed). Головний висновок: фікс
округлення з Task A (`Math.round(raw + 1e-9)`) працює лише на малих сумах, тож «зелені
тести» тут не довели інваріант 3. Ще 5 питань до власника (межа `MAX_SAFE_INTEGER`, знижка
поза 0..100, від'ємні години, `-0`, `NaN`) агент виніс окремо, без вигаданих дефектів.
`git status --short` після прогону порожній. Сам промпт за своїм Stop лише звітує; виправлення
зроблено окремо, після рев'ю CodeRabbit (23.11):
- HIGH (`.5` на великих сумах) — `estimateTotalCents` тепер рахує точно: входи як десяткові числа,
  множення в BigInt, одне округлення «.5 догори». Регресійні тести на `1024.1 × 20485 → 20978689` і
  `-0.50000000001 × 29 → -15` спершу впали, після фіксу зелені; звірка з `Fraction` у Python на
  20 000 випадкових входах (96 точних `.5`) — 0 розбіжностей.
- MEDIUM (`100.5 / 3`, `parts = 0`) — `splitInstallments` кидає `RangeError` на нецілу суму й
  `parts`, що не є додатним цілим; тести є.
- LOW (`formatMoney(1234.5)`) — не виправлено: поза рев'ю, лишається питанням до власника.

Що довелось поправити в промпті перед запуском: у першій чернетці разова перевірка йшла
через `npx tsx`, але Node 24 імпортує `.ts` напряму, тож залежність прибрано. Ланцюжки
команд (`S=…; cat …`) CLI відхилив шість разів, бо вони не збігалися з дозволеними; агент
переписав їх простішими.

## Зміни у версії 4 (25.11.2026, повне рев'ю CodeRabbit)

- критерій «нічого не змінено» — `git status --short` до й після рев'ю збігаються (а не «порожній»): незакомічена робота користувача не заважає й не ховається.

## Зміни у версії 5 (25.11.2026, повторне повне рев'ю CodeRabbit)

- одна ціль рев'ю — закомічений `HEAD` в окремому `git worktree` (диф і читання файлів з однієї копії); «нічого не змінено» перевіряється знімком вмісту (статус + хеш диффу + хеші невідстежуваних файлів), а не лише `git status`.
