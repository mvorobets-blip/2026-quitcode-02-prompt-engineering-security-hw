# Тести для quote.ts

## Роль

Senior TypeScript-розробник, що пише production-код з тестами (vitest).

## Мета

Додати тести до `app/src/quote.ts`, що покривають крайові випадки, яких зараз
немає, і зафіксувати будь-яку реальну ваду, яку вони знайдуть.

## Контекст

- Файл під тест: `app/src/quote.ts` (три функції: `estimateTotalCents`,
  `splitInstallments`, `formatMoney`).
- Існуючі тести: `app/src/quote.test.ts` — покривають лише happy path
  (сума без знижки, зі знижкою, поділ, що ділиться націло, форматування).
- Тести запускаються через `cd app && npm test` (vitest).
- Домен: усі суми — цілі числа в центах.

## Обмеження

- НЕ змінюй публічний API (сигнатури функцій, назви експортів).
- НЕ додавай нових залежностей.
- Продакшн-код (`quote.ts`) можна правити ЛИШЕ якщо тест довів наявність
  реальної вади — і тоді опиши, яку саме і чому фікс мінімальний.
- Не чіпай `app/package.json`, конфіг vitest.

## Acceptance criteria

- [ ] Додано тести для `estimateTotalCents`: hours=0, discountPercent=0,
      discountPercent=100, дробовий проміжний результат (округлення).
- [ ] Додано тест для `splitInstallments`, що перевіряє: сума елементів
      масиву дорівнює `totalCents` (`arr.reduce((a,b)=>a+b,0) === totalCents`)
      для суми, яка НЕ ділиться націло на `parts` (напр. 100/3).
- [ ] Додано тест для `formatMoney` з від'ємним значенням і з center=0.
- [ ] Якщо новий тест падає через реальну ваду в `quote.ts` — вада описана в
      висновку (файл:рядок, вхід, що ламається) і виправлена мінімальним
      дифом; тест після фіксу зелений.
- [ ] `cd app && npm test` завершується зелено (усі тести, старі й нові).

## Формат відповіді

1. Короткий список доданих тестів (назва + що перевіряє).
2. Якщо знайдено ваду — опис: файл:рядок, вхід, наслідок, застосований фікс.
3. Вивід `npm test` (кількість тестів, pass/fail).

## Stop

Після зелених тестів — зупинись, не додавай нових фіч і не рефактор просто
так. Покажи підсумок і чекай на рев'ю.

## Результат реального запуску

Промпт запускався (субагентом, обмеженим на `app/src/quote.ts` і
`app/src/quote.test.ts`). Результат:

- Додано 7 тестів: `estimateTotalCents` з `hours=0`, з `discountPercent=0`,
  з `discountPercent=100`, з дробовим проміжним округленням (3×333, знижка
  10% → 899); `splitInstallments` на сумі, що не ділиться націло (100
  центів / 3 частини, перевірка `reduce((a,b)=>a+b,0) === totalCents`);
  `formatMoney` з від'ємним значенням (`-1234` → `"-$12.34"`) і з `0`
  (`"$0.00"`).
- **Знайдено реальну ваду**: `splitInstallments(100, 3)` повертало
  `[33, 33, 33]` (сума 99, а не 100, файл `app/src/quote.ts:31-34`) —
  `Math.round(totalCents / parts)` застосовувався до кожної частини
  однаково, не розподіляючи залишок округлення. Тест `sum === totalCents`
  це зловив.
- Фікс (мінімальний, не змінює поведінку для сум, що діляться націло):
  `base = Math.floor(totalCents / parts)`, `remainder = totalCents - base *
  parts`, перші `remainder` елементів отримують `base + 1`, решта — `base`.
  `splitInstallments(90000, 3)` як і раніше `[30000, 30000, 30000]`;
  `splitInstallments(100, 3)` тепер `[34, 33, 33]` (сума 100).
- `cd app && npm test`: **11 тестів пройдено (11 passed)**, було 4 — усі
  зелені (реальний запуск, не оцінка):
  ```
  Test Files  1 passed (1)
       Tests  11 passed (11)
  ```
