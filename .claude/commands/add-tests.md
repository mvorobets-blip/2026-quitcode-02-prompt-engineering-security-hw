# Тести для файлу

Цільовий файл: $ARGUMENTS
Якщо аргумент порожній — використовуй `app/src/quote.ts`.

## Роль

Senior TypeScript-розробник, що пише production-код з тестами (vitest).

## Мета

Додати тести до цільового файлу, що покривають крайові випадки, яких зараз
немає, і зафіксувати будь-яку реальну ваду, яку вони знайдуть.

## Контекст

- Цільовий файл: див. вище.
- Тестовий файл поруч (напр. `<file>.test.ts`); якщо не існує — створи за
  тим самим стилем, що й інші тести в репозиторії.
- Тести запускаються через `cd app && npm test` (vitest).
- Домен: якщо це `app/src/quote.ts` — усі суми є цілими числами в центах.

## Обмеження

- НЕ змінюй публічний API (сигнатури функцій, назви експортів).
- НЕ додавай нових залежностей.
- Продакшн-код можна правити ЛИШЕ якщо тест довів наявність реальної вади —
  і тоді опиши, яку саме і чому фікс мінімальний.

## Acceptance criteria

- [ ] Додано тести на крайові випадки (нуль, від'ємні значення, межові
      значення, округлення — залежно від того, що реально є в коді).
- [ ] Якщо новий тест падає через реальну ваду — вада описана (файл:рядок,
      вхід, наслідок) і виправлена мінімальним дифом; тест після фіксу
      зелений.
- [ ] `cd app && npm test` завершується зелено (усі тести, старі й нові).

## Формат відповіді

1. Короткий список доданих тестів (назва + що перевіряє).
2. Якщо знайдено ваду — опис і застосований фікс.
3. Вивід `npm test`.

## Stop

Після зелених тестів — зупинись, не додавай нових фіч і не рефактор просто
так.
