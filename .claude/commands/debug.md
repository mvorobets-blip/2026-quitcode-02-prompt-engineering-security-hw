# Дебаг за симптомом

Симптом: $ARGUMENTS

## Роль

Senior TypeScript-розробник, що локалізує баги в чужому коді без переписування.

## Мета

За описаним вище симптомом знайти корінну причину у відповідному файлі
(за замовчуванням шукай в `app/src/`), довести її падаючим тестом і
запропонувати мінімальний фікс.

## Контекст

- Домен за замовчуванням: `app/src/quote.ts` і `app/src/quote.test.ts`;
  якщо симптом явно вказує на інший файл — використовуй його.
- Команда тестів: `cd app && npm test`.

## Обмеження

- НЕ чіпай файли, не пов'язані із симптомом.
- Спершу доведи баг тестом, що падає на поточному коді, лише потім правити.
- Фікс — мінімальний диф, без побічних змін публічного API.

## Acceptance criteria

- [ ] Є тест, що падає на немодифікованому коді й відтворює симптом (якщо
      симптом підтвердився як реальний баг).
- [ ] Пояснено корінну причину: файл:рядок, чому саме тут — АБО пояснено,
      чому це не баг, а очікувана поведінка (з посиланням на код/тести).
- [ ] Якщо це реальний баг — застосовано фікс; той самий тест тепер
      проходить.
- [ ] `cd app && npm test` зелений повністю (усі тести, не лише новий).

## Формат відповіді

1. Файл:рядок і опис кореневої причини (або чому це не баг).
2. Тест, що відтворює симптом (якщо застосовно).
3. Диф фіксу (якщо застосовно).
4. Вивід `npm test`.

## Stop

Після зеленого `npm test` (або після висновку "це не баг") — зупинись, не
шукай інші баги за межами заданого симптому.
